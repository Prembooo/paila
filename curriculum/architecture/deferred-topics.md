# Deferred-Topics Register

Any topic proposed for Phase 1 that belongs to a later phase, or that violates a Phase 1 scope boundary, is recorded here and **excluded from Phase 1 content** (Requirements 2.2, 2.3, 2.4, 2.5).

Entry schema: `id` (DEF-nnn), `topic`, `assigned_phase` (2 Digital Worker / 3 Digital Creator / 4 Technology Builder), `reason`.

| ID | Topic | Assigned phase | Reason (violated boundary) |
|---|---|---|---|
| DEF-001 | Coding / programming | 4 — Technology Builder | Excluded by Req 2.2 (no coding in Phase 1) |
| DEF-002 | Spreadsheets / office productivity tools | 2 — Digital Worker | Excluded by Req 2.2 (no productivity tools) |
| DEF-003 | Certification / exam preparation | 2 — Digital Worker | Excluded by Req 2.2 (no certification) |
| DEF-004 | Technical career / vocational job training | 2 — Digital Worker | Excluded by Req 2.2 (no career training) |
| DEF-005 | Installing software / changing system settings | 2 — Digital Worker | Req 2.3 (no admin configuration tasks for learners) |
| DEF-006 | Managing app permissions / device administration | 2 — Digital Worker | Req 2.3 (admin configuration) |
| DEF-007 | Content creation tools (video editing, design apps) | 3 — Digital Creator | Belongs to a later phase |
| DEF-008 | Financial/investment advice; earning online | — (out of scope) | Req 11.3 (money is taught as safety, not finance) |

## How to use
When authoring or reviewing, if a proposed topic or activity matches any exclusion above (or a new one), add a row here instead of putting it into a lesson. This keeps the Phase 1 scope clean and records *why* it was deferred.
